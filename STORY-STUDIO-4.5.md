# Story Studio 4.5

Stop any active batch, then reload the existing D:\pfGG extension from Chrome's Extensions page. Version 4.5.9 appears in its header. Updating the same loaded folder preserves existing Chrome storage. See [FLOW-FIX-4.5.9.md](FLOW-FIX-4.5.9.md) for the Chrome argument-serialization fix, and [FLOW-BACKEND-4.5.8.md](FLOW-BACKEND-4.5.8.md) for the backend-only Flow transport, confirmed reference IDs, parallel requests and Copy diagnostics. The older native-picker notes describe previous versions. See BACKEND-REFERENCES-4.5.7.md for location mapping and CLASSIC-PHOTO-4.5.5.md for Classic photo and figure direction.

Story collection controls appear together above the panel grid. **Stop** stops taking new work and saves progress; requests already sent to Google may finish first. **Resume** continues saved chapters and keeps completed panels. **Start over**, available after stopping, replans and regenerates every saved chapter using its saved cast and settings. It confirms the new generation before starting and stores a backup of the previous collection. Character presets are preserved.

- Select **Shadow Slave · load full cast** at the top of Story Studio. All 17 distinct characters load automatically from the 19 supplied designs. Sunny and Nightmare each have selectable alternate forms. The previous cast is backed up under a separate, dated name in the collection selector, and its named characters are also added to My saved characters. Custom characters and their design notes remain editable.
- The selected art mode stays selected when loading a cast. Webtoon uses the supplied illustrated samples as defaults; custom art references take precedence. Those samples guide art treatment only. Photorealism continues using its original image rendering instructions.
- Webtoon narration uses consistent black cards and bold italic serif text. Dialogue uses one bundled comic font and white bubbles. Text sits in available panel space, with an expanded gutter only when necessary to protect figures and important details. Complete text is retained.
- Gemini speaker names match character aliases and both NPC names and roles (including punctuation/case differences). Dialogue from outside the visible cast remains an off-screen voice with no bubble tail; it does not add a person or upload unrelated character references. A speaker mismatch no longer rejects the complete chapter.
- Completed Gemini JSON is picked up after a short stability check. Already-loaded planner tabs proceed immediately. A response with no new text for three minutes triggers recovery, and each planning attempt has an eight-minute response limit. Story recovery has two attempts without nested request retries. Parsed drafts persist before validation, so Resume can recheck a saved response without asking Gemini to write the chapter again.
- Paste the current chapter and optionally add up to three queued chapters. Additional drafts can be appended while a collection is running, up to four chapters total. Parallel mode runs three panel workers; each owns its references, generated media and retry state. Chapters and PDF pages retain source order even when images finish out of order.
- Google tabs open in the background. Keep Chrome running and signed in. Temporary planning, setup, upload and download failures retry with limits. A restart, sign-in requirement, exhausted quota or security rejection can require Resume. Unconfirmed paid requests require an explicit resubmit choice to avoid accidental duplicate charges.
- Successful panels and storyboards are stored in IndexedDB. Resume skips completed panels. The preview grid uses small thumbnails; opening or saving a panel reads the full image.
- Once every chapter is complete, one PDF is stored locally and sent through the configured Telegram bot when Telegram delivery is enabled. No PDF downloads automatically. Use **Save complete PDF**, or **Send PDF to Telegram** to retry delivery. A delivery failure preserves the saved PDF.
- PDF page boundaries occur between whole panels. Webtoon trimming is conservative: only verified empty export footers and an isolated recognized watermark in such a footer are removable. If a logo overlaps textured artwork or protected content, the image is preserved rather than cutting through it. A universal watermark-removal guarantee is not possible with this conservative crop.
